# GFC Client

Unreal Engine 5.7 front end for **Galactic Federation Coin**: browse the seed
feed, view 3D models, images, video and audio in the app, manage your GFC
wallet, send GFC, back up your wallet, and share seeds to X.

**Mobile first.** The first build ships on Android phones. Windows is the
development and test loop, set up to behave like a phone (mobile renderer,
portrait, touch-first). Budgets and the plan: [docs/roadmap.md](docs/roadmap.md).
Cache rules: [docs/cache-policy.md](docs/cache-policy.md).

The backend and its API live in [subvertio/GFCCoin](https://github.com/subvertio/GFCCoin)
(see `docs/build-your-own-frontend.md` there, and `/docs` on any node).

The whole UI is built in C++ (UMG constructed in code), so the project runs
without hand-made editor assets. Designers can swap in Widget Blueprints later:
see [docs/ui-spec.md](docs/ui-spec.md).

## Layout

```
GFCClient.uproject
Config/                  DefaultEngine.ini (mobile rendering, Android, caches), DefaultGame.ini (node, budgets)
Source/GFCApi/           Runtime module: HTTP client, JSON, session storage, cache owner, deep links,
                         qualified views, glTF parser, Android glue (GFCApi_UPL.xml), tests
Source/GFCClient/        Game module: game mode, player controller, UI/ screens, Viewer/ (3D + media)
Content/GFC/             M_GFCModel, the viewer material (generated by Scripts/MakeAssets.ps1)
Scripts/                 Build, run, test, asset and local-node scripts (PowerShell)
docs/                    UI spec, roadmap, cache policy
```

## Requirements (Windows)

- Unreal Engine **5.7** (Epic Games Launcher), default path `C:\Program Files\Epic Games\UE_5.7`.
  Set `UE_ROOT` if yours is elsewhere.
- Visual Studio 2022 with **Game development with C++** (MSVC v143, Windows SDK).
- Git LFS (`git lfs install`) before cloning: binary assets are stored in LFS.
- For the local test node: Python 3.11+ and a GFCCoin checkout with its `requirements.txt` installed.

## Build

```powershell
.\Scripts\Build.ps1
```

This builds **GFCClientEditor** and **GFCClient** (Development, Win64) with
UnrealBuildTool. Use `-Targets Editor` for the editor only. If the compiler
runs out of memory (C3859 / C1076), lower parallelism: `-Jobs 4`.

### Same interface on every build

The layout sizes itself to the screen: `UGFCDPIScalingRule` scales by the screen's shortest
side on phones, so a 1080 px wide phone and a 720 px one show the same layout, just sharper or
softer. A build looks the same as everyone else's as long as it comes from the current branch and
these settings in `Config\DefaultEngine.ini` are unchanged:

- `[/Script/Engine.UserInterfaceSettings]`: `UIScaleRule=Custom`,
  `CustomScalingRuleClass=/Script/GFCClient.GFCDPIScalingRule` and the `UIScaleCurve`;
- `[/Script/AndroidRuntimeSettings.AndroidRuntimeSettings]`: `bEnableNewKeyboard=True`
  (otherwise every text field opens a full-screen white box on Android).

`Build.ps1` and `PackageAndroid.ps1` run `Scripts\CheckLayout.ps1` first and stop if any of
this is different, including an override in `Saved\Config` left by the editor, or a checkout
from before the layout existed. Don't change these in the editor's Project Settings; if the
scale has to change, change the curve in both `DefaultEngine.ini` and `CheckLayout.ps1`.

The viewer material is generated from a script, so there's nothing to author by hand:

```powershell
.\Scripts\MakeAssets.ps1
```

## Run

```powershell
.\Scripts\Run.ps1
```

Opens the client in a phone-shaped portrait window (432x900) rendering at the
mobile feature level (`-featureleveles31`), the way phones render. `-Desktop`
uses the desktop renderer instead. The first launch compiles shaders for a few
minutes; later launches are quick.

Other options: `-Node <url>`, `-Screen wallet|feed|seed:<id>`, `-Link "gfc://seed/<id>"` (deep link test).

To open the editor, double-click `GFCClient.uproject`, then choose **Settings >
Preview Platform > Android Vulkan** to preview as a phone.

## Point it at a node

By default the client talks to `https://node.galacticfederation.tech`.

- **Per launch:** `-GFCNode=http://127.0.0.1:8000`, or `.\Scripts\Run.ps1 -Node http://127.0.0.1:8000`.
- **Per user:** the node box at the bottom of the login screen (remembered).
- **Project default:** Project Settings > Game > **GFC API**, or `Config/DefaultGame.ini`:

  ```ini
  [/Script/GFCApi.GFCApiSettings]
  NodeBaseUrl="https://node.galacticfederation.tech"
  ShareBaseUrl="https://node.galacticfederation.tech"
  ```

  Keep the quotes: without them the ini parser treats `//` as a comment.

A session belongs to the node that issued it; switching nodes logs you out.

## Caches (keep C: free)

- Derived data goes to `DerivedDataCache/Local` **inside the project folder** (ignored by git), set in
  `Config/DefaultEngine.ini`. This project doesn't use the machine-wide Zen store on C:.
- Don't set `[Zen.AutoLaunch] DataPath` per project. UE treats a changed default Zen path as a migration and
  **deletes the old machine-wide store**, and other UE 5.7 projects then delete the new one.
- Shader and build intermediates go to `Intermediate/` in the project folder.
- To move derived data for **every** project instead, set a user environment variable:

  ```powershell
  [Environment]::SetEnvironmentVariable('UE-LocalDataCachePath', 'D:\UnrealCache\DDC', 'User')
  ```

- The app's own runtime cache (downloaded media and models) is session-only: see [docs/cache-policy.md](docs/cache-policy.md).

## Security

- Wallet private keys never reach the client. The node signs transfers and holds keys encrypted with your password.
- The token is sent only as `Authorization: Bearer …` and is never logged.
- On Windows the saved token is encrypted with **DPAPI** (bound to your Windows account) in
  `Saved/SaveGames/GFCSession.sav`. Android Keystore storage is a TODO for the Android build
  (`Source/GFCApi/Public/GFCSessionStore.h`).
- Wallet backups are passphrase-encrypted by the node and saved to `Saved/Backups/` (in the installed Windows
  app, `%LOCALAPPDATA%\GFCClient\Saved\Backups`). Move them somewhere safe
  and store the passphrase apart.
- Uploaded models are untrusted: the parser bounds-checks every offset, never follows external URIs, and
  enforces size, triangle and texture budgets before building anything.

## Test

### Unit tests (headless)

```powershell
.\Scripts\RunTests.ps1
```

Runs the `GFC` automation tests in `UnrealEditor-Cmd` with `-nullrhi`: JSON parsing, error handling, amounts,
URL building, settings, DPAPI storage, client behaviour offline, deep links, qualified views, cache accounting,
and the 3D model parser's budgets. Also in the editor: **Tools > Session Frontend > Automation**, filter `GFC`.

### End-to-end against a local node

Never run the end-to-end test against the public node: it registers throwaway accounts.

```powershell
# Terminal 1: an isolated node on 127.0.0.1 with scratch data and P2P switched off
.\Scripts\RunLocalNode.ps1 -Port 8100 -Fresh
```

```powershell
# Terminal 2: demo seeds (an image, a textured 3D planet, an audio loop), then the tests
py -3 .\Scripts\seed_local_node.py http://127.0.0.1:8100
.\Scripts\RunTests.ps1 -E2ENode http://127.0.0.1:8100 -ExpectSeed <one of the printed ids> -SaveSession
.\Scripts\Run.ps1 -Node http://127.0.0.1:8100
```

`RunLocalNode.ps1` runs the GFCCoin backend (`-BackendDir`, default `D:\projects\GFC`) through
`Scripts/local_node.py`, which turns off the backend's P2P sync so test data never leaves your machine. The E2E
test registers, logs in, creates wallets, reads balance and history, checks transfer errors, reads the feed and
a seed, exports a backup, and logs out (checking the token is revoked). `-SaveSession` leaves its test user
logged in so `Run.ps1` opens straight to the feed.

The memory and disk baseline check for the 3D viewer is in [docs/cache-policy.md](docs/cache-policy.md).

## Windows app (installer)

```powershell
winget install JRSoftware.InnoSetup     # once: builds the installer
.\Scripts\PackageWindows.ps1
```

This builds and cooks a standalone **Shipping** Win64 app into `Packaged\Windows\` and then the installer
`Packaged\GFC-Setup-<version>-<commit>.exe`. Options: `-Config Development` (logs and console), `-NoInstaller`
(folder only), `-SkipBuild` (redo just the installer), `-Jobs 4` (compiler memory).

The installer (`Installer/GFC.iss`):

- installs per user without an admin prompt (or for all users, which it offers), into `%LOCALAPPDATA%\Programs\GFC`;
- adds a **Start menu** entry, an optional desktop shortcut, and an uninstaller in Settings > Apps;
- registers **`gfc:` links**, so share links (`gfc://seed/<id>`) and the return from phone verification
  (`gfc://verified`) open the app;
- installs the Visual C++ runtime only if the PC doesn't have it (that step asks for admin).

The packaged app runs as **one copy** (`Source/GFCApi/Private/GFCSingleInstance.cpp`). Opening a `gfc:` link or
the shortcut while it runs passes the link to the open window over a named pipe and brings it to the front.
Editor and `Run.ps1` runs aren't affected. The first window is 1280x800 and resizable
(`Config/Windows/WindowsGameUserSettings.ini`).

An installed app keeps its data in `%LOCALAPPDATA%\GFCClient\Saved` (signed-in session, settings, and wallet
backups in `Saved\Backups`). Uninstalling leaves that folder, so a reinstall stays signed in.

The app icon comes from one piece of artwork, `Build/Icon/GFCIcon.jpg` (the Pleiades constellation).
`.\Scripts\MakeIcon.ps1` makes the Windows `Build/Windows/Application.ico` and the Android icons in
`Build/Android/res` from it: a rounded square for old Android, and an adaptive icon for Android 8+ that the
launcher masks to its own shape. Unreal uses those instead of its default icon. To change the icon,
replace the .jpg, run the script and commit the results. The installer isn't code-signed yet, so Windows
SmartScreen shows "unknown publisher" on first run.


6. Package from **Platforms > Android > Package Project** (ASTC), or:

### Debug builds on your phone

Phone builds default to **Development**, not Shipping (`Config/DefaultGame.ini`). Development builds have:

- all GFC logging at Verbose (`[Core.Log] LogGFCApi=Verbose`);
- the console (four-finger tap) with `stat fps`, `stat unit`, `gfc.cache`, `gfc.cache.overlay 1` and `gfc.debug`;
- the **debug overlay**: fps, API calls (in flight, recent, errors), cache usage, the live 3D item's memory, and
  process memory. Toggle it with a **three-finger tap**, `gfc.debug`, or by launching with `-GFCDebug`;
- crash call stacks and `ensure` failures written to the log.

**1. Turn on USB debugging (once).** On the phone: Settings > About phone, then tap **Build number** seven
times to unlock Developer options. Then Settings > System > Developer options: turn on **USB debugging**.
Connect the USB cable and accept the "Allow USB debugging?" prompt (tick "Always allow from this computer").

**2. Check the phone is visible.** `adb` comes with the Android SDK (step 3 above):

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" devices
```

It should list your phone as `device`, not `unauthorized` (accept the prompt on the phone) or empty
(try another cable or USB port).

**3. Build and install.** Package Development (step 6 above), then install over any previous copy:

```powershell
& "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" install -r "D:\projects\GFC-Client\Packaged\Android_ASTC\GFCClient-Android-Development-arm64.apk"
```

(The exact `.apk` name is printed at the end of packaging. If it was packaged with OBB data, use the
`Install_GFCClient-Android-Development-arm64.bat` next to it instead.)

**4. Capture logs to D:.** Start this before opening the app; stop it with Ctrl+C:

```powershell
New-Item -ItemType Directory -Force D:\GFCLogs | Out-Null; & "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe" logcat -s UE GFC AndroidRuntime | Tee-Object -FilePath "D:\GFCLogs\gfc-$(Get-Date -Format yyyyMMdd-HHmmss).log"
```

`UE` is the engine's log tag (every `LogGFCApi` line is there), and `AndroidRuntime` catches Java crashes in the
camera or picker bridge. Logs never contain tokens or passwords.

**If packaging stops because the toolchain is missing** (it's not installed on this machine yet), work through
steps 1 to 5 above first: Android in the Epic launcher, Android Studio, `SetupAndroid.bat` (NDK r27c
`27.2.12479018`, platform `android-34`, build-tools `35.0.1`, CMake `3.22.1`), then Turnkey `VerifySdk`.

### App Links (shared links open the app)

Links shared on X look like `https://node.galacticfederation.tech/p/{id}`. The app claims them with an
`autoVerify` intent filter (`Source/GFCApi/GFCApi_UPL.xml`), with `gfc://seed/{id}` as a fallback. Android only
trusts the claim if the node's `/.well-known/assetlinks.json` lists the SHA-256 fingerprint of the certificate
that signed the installed app. The node reads them from `GFC_ANDROID_PACKAGE=tech.galacticfederation.gfc` and
`GFC_ANDROID_CERT_SHA256` (comma-separated, so list every one below).

Get the fingerprints (`keytool` comes with Android Studio's JDK). The debug key, which development builds use:

```powershell
& "$env:ProgramFiles\Android\Android Studio\jbr\bin\keytool.exe" -list -v -keystore "$env:USERPROFILE\.android\debug.keystore" -alias androiddebugkey -storepass android -keypass android | Select-String 'SHA256:'
```

Your upload key (keytool asks for its password; never paste it into chat or scripts):

```powershell
& "$env:ProgramFiles\Android\Android Studio\jbr\bin\keytool.exe" -list -v -keystore "D:\keys\gfc-upload.keystore" -alias gfc-upload | Select-String 'SHA256:'
```

With **Play App Signing**, Google re-signs the app, so the production fingerprint comes from Play Console >
Test and release > App integrity > App signing key certificate. Add it too once the Play listing exists.

On a device, once Android is set up:

```powershell
adb shell pm get-app-links tech.galacticfederation.gfc
```

```powershell
adb shell pm verify-app-links --re-verify tech.galacticfederation.gfc
```

```powershell
adb shell am start -a android.intent.action.VIEW -d "https://node.galacticfederation.tech/p/<seed id>"
```

```powershell
adb shell am start -a android.intent.action.VIEW -d "gfc://seed/<seed id>"
```

`get-app-links` should show `node.galacticfederation.tech: verified`. Anything else (such as `1024` or
`legacy_failure`) means the fingerprint in `assetlinks.json` doesn't match the installed build. On PC, the same
link parsing can be tested with `.\Scripts\Run.ps1 -Link "gfc://seed/<id>"`.
